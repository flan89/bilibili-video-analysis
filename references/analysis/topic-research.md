# Topic Research Analysis Protocol

> 适用 Intent：`topic_research`
>
> 目标是**比较多个视频**：识别共同认识、真正分歧、互补信息和孤立观点，并让结论能够回查到具体视频证据。不要把跨视频研究写成“罗列每个视频的总结”，也不要把当前样本写成B站整体认知。

最终输出结构服从用户问题。

## 1. 先固定研究问题

开始搜索前，把用户的研究问题写清楚（内部即可）。之后每次被高热视频吸引时，回到这个问题检查：它真的覆盖用户问的东西吗？

搜索结果中的播放量、排名、标题吸引度会持续把注意力拉向热门内容。**先固定问题，是防止样本被热度绑架的第一道防线。**

## 2. 区分三种数量

跨视频研究中最常见的错误是把“数量”混着用：

- **视频数量** ≠ **独立创作者数量**：同一 UP 主的 5 个视频只代表 1 个创作者视角；
- **独立创作者数量** ≠ **独立观点数量**：5 个不同账号可能都只是转载、共用脚本、转述同一个来源或同一起事件；
- 判断来源是否相互独立前，先检查转载声明、相同脚本、共同资料来源、互相引用和明显相同的叙事结构。只看到账号不同，不足以称为“独立印证”；
- 无法完成上述检查时，可以说“多个视频出现同一说法”，但不要写“多个独立来源证实”。

样本描述中使用哪个数量就用哪个，不要用“很多视频都提到”来暗示独立观点多。

## 3. 四种跨视频关系

对每个重要结论，判断它在样本中属于哪种关系：

- **共同认识**：当前可用样本中，全部视频都给出一致的方法 / 结论 / 事实，表述为 `N/N`；只有确认来源未共享时，才能进一步称为相互独立的共同认识；
- **多数认识**：不是全部视频一致，但达到多数，表述为 `n/N`，例如“5 个可用样本中有 3 个提出……”；
- **真正分歧**：不同视频对同一问题给出不同判断，且各方都有理由；分歧要呈现双方理由，不要裁决谁对，除非证据明显；
- **互补信息**：不同视频覆盖同一主题的不同侧面（例如一个讲原理、一个讲实操陷阱）；
- **孤立观点**：只有一个视频提出、其它视频未涉及，表述为 `1/N`。孤立不等于错误，但要标注“当前样本中仅一个视频提出”。

注意：

- 关系判断的分母 `N` 只计算该结论上有可用内容证据的视频；缺字幕或未分析正文的视频不能悄悄算进分母；
- 同一结论出现在 3 个视频里，**不自动等于平台共识**——先排除共同来源 / 互相引用（§2）；
- “共同认识”的表述应限定为“当前样本中的共同点”，不是“B站普遍认为”；
- 搜索和推荐机制会影响哪些视频进入样本。`n/N` 描述的是本次可用样本，不是对B站总体比例的估计。

## 4. 发现信号 ≠ 内容证据

搜索阶段可用的字段——播放量、发布时间、排名位置、标题匹配度、平台报告总数——**只能用于发现和描述候选**。

它们不能支持：

- 内容正确性（播放量高 ≠ 讲得对）；
- 代表性（排名靠前 ≠ 最值得深入）；
- 主题热度结论（除非用户明确只要快照描述）。

跨视频结论必须来自视频正文（Transcript）、观众反馈（评论 / 弹幕）或画面证据，且回到具体来源：视频的 BV 号 + 字幕时间、评论 ID、弹幕时间或 Frame 时间。

### 发现来源的机制语义

不同发现来源表达不同的平台信号，分析时不能混写：

- **关键词搜索命中**表示关键词相关性信号；
- **当前热门列表**表示平台热门机制的**当前选择快照**：它不是全站客观质量排名，不是排行榜；`discoveryReason`（如"百万播放"）只是平台推荐理由标签；
- **当前热搜词条**表示平台**搜索关注度**的当前快照：不是事件背景，不是需求强度排名；`heatScore` 只描述本次快照；`isCommercial` 缺失不等于自然热度；词条不是视频，研究词条内容必须经过第二步搜索；
- **关联推荐列表**表示平台推荐机制的**邻接关系快照**：不保证主题等价、观点相关或代表性抽样；候选与种子相邻只代表推荐链关系，不能写成"同主题代表视频"，需要覆盖主题时应补一次关键词搜索并说明两个来源各自的角色；
- 同一个主题同时出现在多个来源，可以增强"当前可见度较高"的假设，但不能证明长期趋势；
- 不同来源的候选不能简单合并后按位置或热度排序比较。

基于热门快照的轻量归纳（类型分布、可见主题）必须限定为"本次热门页面观察"，并公开 `observedAt`、查看页码与候选数量。

## 5. 时间与快照边界

- 搜索是当前时间点的快照（`observedAt`）；“这个主题正在持续上升 / 衰退”需要跨时间点对比，当前只有一次观察，**默认禁止**这类趋势强表述；
- 不同视频发布于不同时间；比较新旧视频的观点时，注意旧视频的结论可能基于当时的环境，不等于作者现在的立场；
- 结论的时间限定：说“目前样本中”“截至本次检索”，不说“现在B站上”。

## 6. 样本不均衡时的比较

- 数据缺失的视频（无字幕、ASR 转写、评论不完整）不能与证据完整的视频等强度比较；
- 明确每个选中视频实际取得了哪些数据来源（可按视频列一个小结：Transcript ✓ / Comments ✗）；
- 某个视频因数据缺失导致无法验证某个跨视频结论时，该结论要么降级为“单视频观察”，要么标注验证缺口。

## 7. Coverage 与禁止的强表述

回答前检查是否公开了：

- 使用了哪些搜索词（含变体）；
- 查询时间（`observedAt`）；
- 查看了多少候选或多少页；
- 深入分析了多少视频、涉及多少独立创作者；
- 哪些视频存在数据缺口。

以下强表述默认禁止，除非用户提供了足以支持它们的额外范围和证据：

- “B站普遍认为”；
- “全网都在讨论”；
- “这个主题正在持续上升”；
- “市场需求已经验证”；
- “这是最好的视频”。

改写为当前样本中的观察（“当前样本的 5 个视频中，4 个都…”）。

## 8. 输出结构

不强制统一研究报告模板。常见组织方式：

- 按用户问题的结构组织（推荐）：用户问方法差异，就按方法分组回答；
- 共同点 → 分歧 → 各自独有 → 样本边界，适合开放式研究请求；
- 按视频逐个总结只适合用户明确要求“每个视频分别讲什么”。

无论哪种结构，重要结论都要能回到具体视频及来源位置。
