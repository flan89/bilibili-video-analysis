# 主题发现策略：从用户问题到差异化样本

`topic_research` 的第一阶段由本文档指导。它回答的是：

> **先选哪个发现来源、用什么搜索词、看多少候选、选哪些视频深入、什么时候停？**

Agent 负责全部语义判断；Tool 只提供一页一页的候选元信息或一组快照。不要试图把本策略程序化。

命令行调用发现 Tool 时默认使用各 Tool 文档给出的 `--compact`，并直接复用已经成功取得的结果。紧凑输出仍保留采集状态和全部警告；不要用 `head`、临时脚本或改换输出格式来重复请求同一页或同一快照。

只有进入 `topic_research` 时才读取本文档；单视频任务不需要。

## 0. 来源选择优先于调用 Tool

`topic_research` 有多个发现来源：关键词搜索（`search-videos`）、当前热门（`popular-videos`）、当前热搜（`hot-searches`）和关联推荐（`related-videos`）。先判断来源，再决定调用：

1. **用户明确指定来源时优先使用指定来源**（"看看热门""现在大家在搜什么""从这个视频找相关的"）；
2. **用户只给主题或问题时，仍以关键词搜索为默认入口**，不要先发明来源；
3. **用户问平台当前关注什么**：选择当前热门或热搜，不要先发明搜索词去搜索；
4. **用户给定具体视频但目标是继续发现相关内容时**，选择关联推荐；用户给定视频且问题针对该视频正文（内容、观点、观众反馈）时，仍走单视频流程，不误触发关联推荐；
5. **不为了"来源全面"同时调用多个来源**；已有来源足以回答时停止，跨来源补充必须有明确证据缺口；
6. **单来源失败不用其它来源静默冒充**：用户要热门而热门接口失败 → 公开失败；关联推荐失败且用户目标允许时，才可用明确标注的关键词搜索作为替代来源。

各来源的机制边界（在最终回答中必须表述）：

- 关键词搜索命中表示关键词相关性信号；
- 当前热门表示平台热门机制的**当前选择快照**，不是全站客观排名，也不是排行榜；
- 当前热搜表示平台**搜索关注度**的当前快照：不是事件背景，不是需求强度排名；`heatScore` 只描述本次快照，禁止跨时间比较或换算趋势；平台返回的商业标记（`isCommercial`）必须如实展示，缺失只表示平台未声明；
- 关联推荐表示平台推荐机制的**邻接关系快照**：不保证主题等价、观点相关或代表性抽样，也不能写成"同主题代表视频"；
- 同一个主题同时出现在多个来源，可以增强"当前可见度较高"的假设，但不能证明长期趋势，也不能证明市场已验证；
- 不同来源不能简单合并后按位置或热度排序。

### 热搜（`hot-searches`）使用流程

热搜词条**不是视频**，Tool 返回词条后即停止，不自动把词条提交给搜索：

1. **只看热搜**（`quick`）：取得一组词条后如实列出（含商业标记），表述快照时间和来源机制边界，不做事件解释，到此停止；
2. **研究某个热搜词**：只展开**一个**与用户目标直接相关的词，用它的 `keyword`（不是 `displayName`）调用 `search-videos`，进入本文档 §1 起的关键词搜索流程，再按 §3/§4 选择少量候选深入；
3. **用户自带热搜词进来**：若当前会话**没有**近期取得的热搜快照，先调 `hot-searches` 核对该词是否在榜，并取得其位置、热度与商业标记，再进入搜索；接口失败或词条已不在榜时如实说明，按用户目标决定继续或停止；当前会话已有刚取得的快照时直接复用，不重复请求；
4. 不要批量展开多个热词，也不要因为某个词"在热搜上"就扩大研究范围；
5. 热搜接口失败时公开失败，不用热门视频标题猜热搜词。

### 关联推荐（`related-videos`）使用流程

关联推荐以一个具体视频为种子，Tool 返回一组候选后即停止，不递归获取"关联视频的关联视频"：

1. **从某个视频继续发现**：调用一次 `related-videos` 取得围绕种子视频的推荐列表，检查候选与种子主题的相关性、创作者差异和内容角色，按 §3/§4 选择少量候选深入；
2. **避免只受推荐链限制**：用户目标是覆盖某主题时，可在关联列表之外补一次 `search-videos`，并在回答中说明两个来源各自的角色；关联推荐与搜索是互补来源，不能被静默混合成单一列表；
3. 候选与种子"主题不同"不是异常：推荐邻接关系本来就不保证主题等价，如实说明即可，不要假装它们同主题；
4. 比较结论必须表述"候选来自平台关联推荐，不是代表性抽样"；
5. 关联推荐接口失败时公开失败，不用关键词搜索结果冒充；用户目标允许时可改用明确标注的 `search-videos` 继续发现。

## 1. 搜索词设计

1. **从用户原始问题形成一个主搜索词**。优先用用户自己的语言，不要先改写成系统术语；
2. **只有候选明显不足或偏离目标时，才增加搜索词变体**，变体不超过两个（例如主题的另一种叫法、英文 / 中文互换、更宽或更窄的表述）；
3. 每个搜索词一次只查一页；是否翻页、换词由你决定，Tool 不自动批量执行；
4. 搜索结果为空时，先怀疑搜索词不匹配（换一个变体），再怀疑主题本身冷门。

## 2. 查看多少候选

默认总共查看约 **20～40 条候选元信息**（约 1～2 页）。

这些数字是默认成本边界，不是必须机械达到的配额：

- 用户只想快速找视频：一页甚至半页就够；
- 用户明确要求深入且证据需要时可以增加；
- 不能突破平台风控和用户要求的范围。

## 3. 候选选择：回答四个问题

对每条值得考虑的候选回答：

1. **这个视频是否直接覆盖用户问题？**
2. **它在样本中承担什么信息角色？**
3. **它是否与已选视频高度重复？**
4. **它能否增加新的观点、方法、场景、反例或时间信息？**

发现阶段通常只有标题、简介或标签等候选元信息，因此这里形成的信息角色只是**初步假设**。不要仅凭标题判断视频的真实立场、方法差异、观点重复度或内容价值；读取正文后再确认，若发现标题误导或内容高度重复，优先从已经查看的候选池替换少量样本，必要时才继续搜索。

优先形成有差异的组合，例如：

- 方法教程 + 原理解释；
- 支持观点 + 反对或限制条件；
- 不同创作者且经检查没有转载、共用脚本或共同来源的经验；
- 新内容 + 必要的较早背景内容。

**播放量高、发布时间新、标题匹配只能帮助初筛。** 不能因为这些字段较高就自动宣布“最有代表性”。平台报告的结果总数、搜索结果中的排名位置都不是内容质量的证据。

## 4. 深入多少个视频

默认深入分析 **3～5 个视频**。

- 每个选中的视频回到 [`data-routing.md`](data-routing.md) §7.2，按 Focus 获取必要数据（主题内容研究通常需要 Transcript）；
- 记录选择理由（相关性和信息角色），但**不向用户展示冗长的内部淘汰清单**——用户关心的是研究结果，不是你对 40 条候选的逐条评审；
- 数据缺失的视频（如无字幕）不能与证据完整的视频等强度比较，在 Coverage 中说明。

## 5. 何时停止搜索

满足以下任一条件时停止扩张：

- **已经得到足够差异化的样本**：3～5 个视频覆盖了问题的不同侧面，继续搜索预计只带来重复；
- **风控**：搜索返回 HTTP 412 或业务 -412 时，停止追加翻页和换词，用已有候选继续或公开无法完成发现；`retryable=true` 表示稍后重试可能有意义，不等于应该立即反复调用；
- **空结果**：主搜索词和变体都为空时诚实停止，说明当前搜索词下没有找到内容；不要编造候选；
- **新增信息很低**：新翻的候选页与已看内容高度重复。

## 6. 公开搜索边界

最终回答至少说明：

- 使用了哪些搜索词（含变体）；
- 查询发生在什么时间（Tool 返回的 `observedAt`）；
- 查看了多少候选或多少页；
- 深入分析了多少视频、涉及多少独立创作者。

搜索是当前时间点的快照，结论只覆盖当前检索和选中样本，不代表B站全部内容。更多跨视频判断方法见 [`analysis/topic-research.md`](analysis/topic-research.md)。
