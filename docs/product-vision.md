# 产品愿景与范围

## 1. 最终愿景

本项目希望帮助用户更深入地理解 B站视频，把其中的知识、观点、方法、表达方式和公开观众反馈整理成结构清楚、能够回查来源的分析结果。

核心不是“把视频总结一下”，也不是替用户自动作出商业决策，而是围绕用户这次真正想解决的问题，把下面几类信息联系起来：

> 创作者说了什么 + 画面如何表达 + 观众如何反应 + 当前证据能够支持什么结论。

## 2. 三层数据价值

### 内容层

主要来源：

- 标题、简介和标签；
- 官方字幕或本地语音转写；
- 关键帧、界面和演示文稿；
- 视频中出现的工具、产品、方法和案例。

主要回答：

- 视频讲了什么？
- 核心观点、理由、案例和限制是什么？
- 教程中有哪些步骤、条件和容易遗漏的细节？
- 哪些内容值得进一步学习、记录或实践？

### 用户层

主要来源：

- 弹幕；
- 评论；
- 评论回复。

弹幕更接近视频时间点上的即时反应。评论更接近观看后的思考、经验、比较和反馈。回复线程可以帮助理解不同观点如何形成，但不能自动代表所有观众。

主要回答：

- 当前样本关注什么？
- 有哪些认同、疑问、分歧和补充经验？
- 哪些反馈与视频中的具体内容有关？
- 数据范围是否足以支持“多数”“共识”等较强表述？

### 上下文层

上下文层用于未来的跨视频主题整理和长期学习积累，例如比较多个视频如何解释同一问题、哪些反馈反复出现，以及不同方案各自适用于什么条件。

当前单视频版本不负责证明趋势、市场规模或商业机会成立。

## 3. 四类使用模式

### 内容学习

目的：把视频里的内容真正学会。

对应任务类型：`content_learn`

常见目标包括核心观点、教程步骤、概念解释、方法提取、工具与场景对应，以及针对视频内容的定向问答。

### 视觉拆解

目的：理解画面、演示和剪辑如何服务内容表达。

对应任务类型：`visual_decode`

常见关注点包括：

- 演示文稿和界面；
- 字幕、构图和视觉层级；
- 剪辑节奏和视觉变化；
- 画面与口播的配合；
- 信息密度和观看负担。

### 观众洞察

目的：理解当前公开反馈样本中的关注点、态度、分歧和使用经验。

对应任务类型：`audience_insight`

分析时必须区分弹幕的即时反应、评论的观看后反馈和回复线程中的局部讨论，并公开抽样、缺失和覆盖范围。

### 产品或市场研究

目的：在用户明确提出产品、需求、竞品、付费、机会或商业问题时，辅助理解视频涉及的产品、工具、用户反馈和行业讨论。

对应任务类型：`market_research`

它不是默认模式。单个视频及其评论区只能帮助发现信号、形成假设和规划后续验证，不能单独证明需求普遍存在、用户愿意付费或市场已经成立。

## 4. 单视频工作方式

输入：

- 一个 B站视频；
- 用户本次分析目标。

运行 Skill 的 Agent：

1. 理解用户真正想完成什么，以及具体关注点和分析深度；
2. 规划完成任务所需的最小数据，并区分必需、可选和替代来源；
3. 只读取并调用当前任务需要的原子 Tool；
4. 根据任务和关注点读取对应的专业分析方法；
5. 使用 Agent 自身模型理解内容、比较来源并选择重要依据；
6. 检查重要结论是否能够回查来源，数据是否覆盖用户要求的范围；
7. 直接回答用户，并在目标满足后停止。

```text
用户目标
  ↓
Agent 选择必要的数据能力
  ↓
元信息 / 字幕 / 画面 / 弹幕 / 评论 / 回复
  ↓
Tool 获取并确定性整理数据
  ↓
Agent 自身模型完成分析
  ↓
带原始位置和范围说明的回答
```

程序不为内容、视觉、观众或市场分析分别实现需要额外模型配置的分析器。只有外部数据获取、媒体处理、确定性整理、受控读取和来源核对需要新增 Tool。

## 5. 产品或市场研究的表达边界

当用户明确要求相关研究时，可以从当前样本中识别：

- 问题和不便；
- 想完成的任务；
- 使用场景；
- 临时替代办法；
- 功能请求；
- 替代产品和竞品；
- 反对理由和行动意向；
- 用户描述问题时使用的原始语言。

但必须遵守：

- 单条抱怨不等于稳定需求；
- 表达购买兴趣不等于已经付费；
- 高赞评论不自动代表全部观众；
- 单个视频评论区不等于市场验证；
- 推断应写成“信号、假设和下一步验证”，不能伪装成事实。

## 6. 当前不追求的目标

当前不追求：

- B站全站爬取；
- 大规模实时监控；
- 自动化创业或投资决策；
- 完整商业情报系统；
- 跨大量视频的趋势和市场规模验证；
- 长期个人知识资产管理；
- 通用视频平台统一协议。

未来可以围绕真实需求扩展跨视频主题比较，但当前开发和回答必须围绕单视频范围收敛。
